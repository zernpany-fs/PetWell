PetWell Design System

The single source of truth for PetWell's UI — derived entirely from the existing frontend, not a redesign.

Source of truth: frontend/src · dusty-blue & ivory "quiet luxury"

Everything below is extracted from the actual code — globals.css, the .pw-* utility layer, the components/ui primitives, and the inline styles used across owner/staff pages. Tokens, colours and class names are reproduced verbatim so this page renders like the product. Where the same pattern is built two different ways in the code, the inconsistency is flagged and a single canonical version is recommended without changing the visual language.

2. Components

Only components that actually exist in the codebase are documented. PetWell has two layers: a set of Base-UI/shadcn primitives in components/ui/* (greyscale tokens), and the product visual language applied directly in pages via .pw-* classes + inline styles. The product layer is canonical for user-facing UI; primitives are used in a few utility spots.

The recurring page skeletons in the app. All authenticated pages sit inside AppShell; public/auth pages use PublicHeader.

Authentication layout

Ivory full-height page, PublicHeader on top, a single centred white card (max 420px, rounded-[20px], p-8, card shadow). Playfair title, form, then a centred secondary link ("Register" / "Log in").

Welcome back

Don't have an account? Register

Dashboard layout

Inside AppShell: max-w-5xl container, py-8, space-y-8. Playfair welcome heading → a 1/3-up stat-card row → a two-panel grid (lg:grid-cols-2) → a primary CTA.

List / CRUD page

max-w-5xl. Header row: Playfair title (26px) left, primary "Add…" pill right. Body: responsive card grid (sm:grid-cols-2 lg:grid-cols-3, gap-4) of interactive .pw-lift cards, or a centred empty state when there's nothing yet.

Detail page

max-w-3xl, space-y-6. A hero card (cover image / placeholder + overlaid action, then title row with an inline "Edit" outline button and meta), followed by a titled section rendering a list of record cards (or an inline empty state).

Form layout

<form class="space-y-4">; related short fields paired in a grid-cols-2 gap-3; full-width fields otherwise. Actions sit in a flex gap-3 row at the end: primary pill first, outline "Cancel" second. Optional fields are labelled "(optional)".

Modal & card layouts

Modal: see the Dialog component (§2) — centred, max-w-sm, footer with right-aligned primary. Card: white surface, 16px radius, border + card shadow, header (Playfair) / content / optional footer bar.

8. Usage rules

  • One primary per view. Use .pw-btn-primary for the single most important action; everything secondary is the outline pill. Never place two gradient primaries side by side.
  • Destructive = danger-tinted, not gradient. Cancel/Reject use the small #FEF2F2/#FECACA/#C4534E pill at 36px.
  • Cards vs. panels. Static information → flat bordered card. Whole card is a link → add .pw-lift. Metric → tinted stat card with a Playfair number.
  • Section spacing. space-y-8 between major page sections, space-y-4 between form fields, gap-4 in card grids.
  • Type hierarchy. Playfair (.font-display) for page/section/card titles and big numbers only; Inter for everything else. Don't set body copy in Playfair.
  • Icons. lucide only, inheriting adjacent text colour; 14–16px inline/in-buttons, 32px in empty states. The paw mark is the brand icon.
  • Radius. Buttons/badges/avatars fully round; inputs & banners 12px; cards 16px; the auth card 20px. Don't introduce new radii.
  • Colour discipline. Blue is the only brand colour; pastels (lavender/peach) are accents on stat cards; reserve danger red for errors/destructive. Apply colour via the tokens in §7, not new hex values.
  • Animation. .pw-fade on page mount, .pw-lift on clickable cards, the built-in hover on primary buttons. Keep motion subtle (≤0.3s).
  • Feedback. Server-action results → sonner toast; validation → inline/banner; never a bare alert().
